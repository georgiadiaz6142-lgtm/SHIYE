## 4. 需要修复的问题

以下优先级为本轮工程建议，不改写正式 PRD。

### 1）P0：两个标签页会互相覆盖已保存的作品

【已确认/实测事实】同一隔离浏览器打开 A、B 两个首页；A 新建“标签页A创建”并确认 IndexedDB 已有该书；B 随后新建“标签页B创建”。读回库只剩 B 的测试书，A 的已保存书消失。没有改动任何真实用户作品。

【已确认/代码事实】[app.js:41](/Users/song/Documents/拾页/shiye-editorial-prototype/app.js:41) 将每个标签页的整个内存 `state` 快照 `put` 到同一个 `workspace` 键。标签页内的 Promise 串行不能约束另一个标签页；启动读库后没有 revision 检查或跨页合并。

【建议设计】正式数据层采用按书／页／资产的事务更新与 revision 冲突检测，冲突时保留副本；跨标签通知只能帮助刷新，不能替代提交时的并发校验。短期原型也至少要拒绝陈旧版本覆盖，而不是仅显示成功。此问题修复并复测前，不让用户把它作为唯一作品存储。

### 2）P1：离开工坊后，迟到的照片加载仍会覆盖当前界面

【已确认/实测事实】拦截并暂缓“用山湖照片体验框选”的同源响应；用户切到书架后再放行响应。标题变回“贴纸工坊”，但侧栏仍选中“我的书架”，页面与导航状态不一致。见[截图](./run-02/late-photo-response.png)。

【已确认/代码事实】[app.js:260](/Users/song/Documents/拾页/shiye-editorial-prototype/app.js:260) 等待照片响应后直接调用 `loadPhoto`；[app.js:276](/Users/song/Documents/拾页/shiye-editorial-prototype/app.js:276) 解码完成后直接 `renderWorkshop()`，没有检查当前页面、请求代次或图片会话。

【建议设计】异步加载绑定 requestId/imageSession 与导航代次；返回后逐次核对，过期结果丢弃。能取消的请求同时中止，但仍须保留结果校验。本次证实的是界面被覆盖，不据此声称已复现作品数据丢失。

### 3）P1：保存失败仍可切回翻阅

【已确认/实测事实】已有测试书中添加文字，注入配额错误后出现“保存失败，请重试”；点击“翻阅”仍隐藏工具并进入 read-mode。未保存内容暂时还在内存，测试没有将其描述为已持久保存。见[截图](./run-02/failed-read-switch.png)。

【已确认/代码事实】[app.js:245](/Users/song/Documents/拾页/shiye-editorial-prototype/app.js:245) 的 mode 分支不等待保存；与已实现等待保存的归架分支不同。不符合[设计文档:416](/Users/song/Documents/拾页/拾页-产品设计文档.md:416)“失败保留编辑状态”的建议设计。

【建议设计】切到翻阅时等待本地提交，失败保留编辑状态和可重试内容；明确区分状态切换与保存完成。

### 4）P2：承诺的双击改文字未生效

【已确认/实测事实】新建测试文字后真实双击（100ms 间隔），对话框未打开，见[截图](./run-02/text-doubleclick.png)。另一路“选中 → 工具栏编辑文字”已通过，因此不是文字整体不可编辑。

【合理推断/代码依据】[app.js:85](/Users/song/Documents/拾页/shiye-editorial-prototype/app.js:85) 在每次 pointerup 后立即重建 editor DOM，而 dblclick 处理绑定在旧 canvas 上；连续点击目标被替换，破坏了双击链路。这一具体事件原因尚未用浏览器事件追踪进一步证实。

【建议设计】无拖动的选择操作不重建整页，保留点击目标；或通过稳定容器处理双击。修复后同时检查单击、拖动、触控与工具栏编辑，避免相互干扰。

## 5. 为什么技术第一关还不能通过

【已确认/代码与实测事实】当前是本机 DOM/CSS 编辑器原型；主要数据在 IndexedDB 的 `data/workspace` 单键，图像为 data URL 字符串。不是正式分区 Blob 数据层。项目范围内没有发现正式 API 工程或项目级 `.env`；不代表 Song 在其他位置没有服务账号。

| 第一关能力 | 当前证据 | 判断 |
|---|---|---|
| 真实自动多主体、点／框交互分割、一句话定位 | 代码只包含预制 SVG 多选和矩形裁切，没有真实模型接口 | 未接入，不能验收 |
| 独立透明贴纸和正式白边生成 | 本次裁切 PNG 为 352×233，82016 个像素中透明像素为 0；白边是 CSS 滤镜参数 | 裁切不是抠图；首页预制透明贴纸不证明工坊能力 |
| AI 文案、排版结构化输出与合法性校验 | 没有真实调用、输出或校验链路 | 未验证 |
| 本地编辑器可复用性 | 正常链路与多数操作通过；发现上述 4 个问题 | UI、坐标与编辑交互可作为基础，数据／异步边界需修正 |
| 正式数据层、身份隔离、同步冲突 | 单个无 owner 的 workspace；已复现跨标签覆盖 | 未达到正式方案；账号隔离、云同步未实现 |
| 生产数据库、对象存储、短信、成本与延迟 | 本轮无实际服务调用证据 | 未验证；需已授权环境与供应商配置 |

还未覆盖：大图／大量页面性能、长期容量、崩溃断电、schema 迁移失败、资源缺失占位、真实设备与 Safari、全部封面／排序／删除书本分支、触控完整拖动链路、跨书复用、登录退出与权限、额度账本和 AI 过期结果。不得把本次通过项扩大成这些能力已通过。
