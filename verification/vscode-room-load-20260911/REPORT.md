# VS Code 集成浏览器首页加载恢复 · 2026-09-11

## 实际环境与错误

此前 Tabbit 和 Codex In-app Browser 的成功结果不代表 Song 使用的 VS Code 集成浏览器。此次经授权读取了实际失败页面及开发工具，确认页面报 `fifth-background_day.webp` 加载/解码失败，控制台还记录过 `first-house_day.webp` 的同类失败。

本地墙面 WebP 为 4096×4096，1,027,654 字节，可被完整解码；网络面板中相应原始静态请求显示 304。失败发生在直接 Image.decode() 路径。未证明浏览器内部触发解码拒绝的具体原因，不将其归因于模型、文件缺失或不支持 3D。

## 修改与恢复验证

给房间贴图先加了一次 fresh fetch + blob 解码恢复后，实际 VS Code 页面的房间贴图通过，但书页 sheep.jpg 随后报同类错误。遂将恢复逻辑集中为 render-pages.js 的 loadPreviewImage，统一用于房间贴图、书本图片和书页图片。

原有成功路径不增加请求；只有直接解码失败才重新读取一次对应的本机静态图片，并释放临时 blob URL。HTTP 拒绝、请求未完成和字节收到后解码失败分别提示。未降低图像画质，未改变模型、API、账户或用户作品。父页面的重复状态提示移到顶部，避免遮挡具体错误。

在 Song 原先失败的 VS Code 首页重新载入后：
- 有声和安静进入按钮出现且可操作。
- 点击安静进入，介绍层消失，播放音乐开关为关闭，书本入口“打开手账，看看示例”出现。
- 收起本轮打开的开发工具，保留恢复后的预览。
- 用户随后切换标签，停止进一步点击；本轮未在该环境完成书本翻页检查。

四项针对实际共享加载函数的验证通过：正常不重试、首次失败后恢复、HTTP 403 明确提示、重复解码失败且释放 blob；三个修改脚本语法及 git diff --check 通过。
