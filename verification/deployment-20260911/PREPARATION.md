## 本地部署目录

执行 `node scripts/prepare-deployment.mjs` 会在系统临时目录生成新的 `source/` 与旁边的 `manifest.json`，不覆盖工作区、不联网、不部署。

- 明确选取服务端和共享 TypeScript 源码、依赖锁文件、构建配置，以及服务端公开清单允许的前端资源。
- 保留场景、翻书资源与授权说明，额外保留前端目录的 LICENSE/NOTICE 等文件。
- 不包含 `.env*`、`.local`、用户作品、邀请码、管理员凭据、Git 数据、历史归档、验证截图、依赖目录或历史压缩包。

- 脚本语法检查通过。这里只验证源文件准备，尚未执行云端构建或 Linux 原生依赖验证。
- `.vefaasignore` 是额外防护；尚未通过真实 CLI 上传验证其匹配行为。实际部署应使用上述显式清单生成的目录，不能直接上传原工作区。

## 发布前还需处理

1. 运行时：项目要求 Node.js >=22.22.0 <23，CLI inspect 默认识别为 `native-node20/v1`。不能原样使用该默认值，也不能未经验证降低项目版本要求。官方 Native Node.js 文档经 CLI 获取正文失败，支持的具体版本需继续核验。
2. 公网接入：当前启动只允许 `127.0.0.1`，Host/Origin 只接受本地地址；需要显式环境配置、HTTPS 同源验证与生产 Cookie 设置，并保留本地默认保护。
3. 持久化：账号、邀请码、作品元数据、图片和配置仍使用本机文件，会话部分在内存。不能直接改到函数临时目录后宣称数据安全；需要确定存储适配及重启恢复方案，再验证跨账号隔离。
4. 初始管理员：需要云端受控初始化方式，不能复制本机账号回执或运行时目录进入部署包。
5. 费用：资源规格与存储方案确定后，再给 Song 具体估算并确认收费资源创建范围。复用网关的确认不等于批准其他资源或无限费用。
6. 验收：云端构建、首页资源、HTTPS、登录/退出、管理员权限、作品自动同步、重启恢复与真实 AI 调用尚未进行；素材商业授权的既有待确认事项仍保留。
