# 自动贴边加载与桌面工具布局修复

日期：2026-09-12。状态：本地代码与隔离浏览器验证完成，尚未发布公网。

## 本轮范围与结果

Song 授权修改自动贴边的加载／超时问题，并将桌面操作区放回照片右侧。

- 工具下载与初始化独立等待，最长 60 秒，界面显示“正在准备贴边工具”；仅在工具就绪、提交像素后开始 20 秒计算计时。加载失败、加载超时、计算超时分别提示，保留照片和选区，不自动循环重试。
- 同一照片的连续修正复用已就绪的 Worker。每个任务带独立编号；取消、换图、离开工坊或切换手工模式会释放相关 Worker，迟到结果不能回填。确认预览仍沿用原保存流程。
- OpenCV 文件采用 Node 内置 gzip，无新依赖。原文件 10,964,323 字节，gzip 后 3,526,614 字节，传输减少约 68%。源文件、算法和 720 像素分析尺寸保持原值。
- 仅内容指纹匹配的 OpenCV URL 使用一年 immutable 缓存。未带版本或版本不匹配时保持重新验证；gzip／identity 使用不同 ETag，支持条件请求与 HEAD。API 与私有文件不进入此缓存。
- 自动贴边在宽度大于 800px 时显示照片左、操作区右；800px 及以下放在照片下方。原手工裁切及云端手动修边布局未改。
- 新 Worker 保留旧页面单次消息协议，避免已打开的旧页面误把“就绪”消息当作计算失败。

本轮产品文件为 `edgecut.js`、`edgecut-worker.js`、`edgecut.css`、`server/edge-tool-assets.ts` 和 `server/app.ts`。相对本轮开始时，`server/app.ts` 只新增导入与公开工具文件中间件两行；其中已有未提交改动完整保留。没有读取或更改 `.local` 中的账号和邀请码文件，没有修改首页、调用真实 AI、上传用户照片、变更云配置或部署。

## 实际验证

- 构建、16 个前端脚本与现有前端类型检查通过；合并保护检查 10 项通过。
- 后端 109 项测试通过，含新增 HTTP 压缩、解压内容一致、版本缓存、ETag、HEAD、拒绝 gzip、私有文件与 API 缓存边界检查。
- [最终浏览器结果](./results-final.json)：8 组隔离 Google Chrome 检查通过。仅使用项目示例照片／合成像素和临时本地数据，测试浏览器与临时服务均已关闭。
  - 连续计算两次只创建一个 Worker、初始化一次；撤销命中结果缓存，不重复计算。
  - 首次 OpenCV 加载人为延迟 22 秒：超过原 20 秒限制后仍显示准备状态，随后真实算法计算成功；后续修正复用 Worker。
  - 加载失败不会循环重试；用户主动重试可恢复。
  - 计算中取消保留上次蒙版；旧任务不会回填；换照片后不出现旧蒙版。
  - 加速计时器的故障注入分别验证计算超时与加载超时，计算超时可主动重试恢复。此项验证错误路径，不代表真实设备的性能测量。
  - 确认后生成包含透明／不透明像素的贴纸，保存与刷新恢复通过。
  - 390px 模拟触控圈选、补点与 Worker 复用通过；320／800／1024px 检查无横向溢出；手工模式入口仍可用。
  - 未启用请求拦截的独立浏览器上下文中，先后创建旧协议、新协议 Worker，服务器仅收到一次 OpenCV 请求；第二次资源 `transferSize=0`，确认浏览器实际使用缓存。
- 已查看[桌面右侧操作区](./desktop-right-panel.png)和[手机底部操作区](./mobile-bottom-panel.png)。

初轮手机测试误等待了被隐藏的首页标志，尚未到达工具页面；修正测试定位器后，手机专项通过。初轮记录保留于 `results.json`，专项结果另存，最终结果为上方 `results-final.json`。该测试问题没有引起产品代码变更。
