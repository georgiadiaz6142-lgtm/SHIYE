# 管理员身份隔离修正 · 2026-09-09

## 问题与改动

代码检查确认：原实现验证邀请码成功后不撤销同浏览器的管理员会话，普通界面也仅在初次加载时读取一次管理员身份。因此曾登录管理员的浏览器切换为邀请码访问时，会沿用管理员入口；这不等同于独立浏览器的普通用户能够越过管理接口鉴权。

- 验证邀请码成功后撤销此前管理员会话并清除管理员 Cookie。重放该旧会话也会被拒绝；无效邀请码不改变原身份。
- 管理员登录清除普通邀请 Cookie，并撤销同浏览器此前的管理员会话。
- 侧栏以服务端当前身份为准，显示管理员名称；普通用户不生成管理工具按钮。
- 登录、退出、改密码和邀请码切换通过无敏感内容的 BroadcastChannel 通知其他标签重新核验身份。页面重新激活、浏览器后退恢复时重新检查；进入管理工具前也重新检查。
- 更新身份仅改动侧栏入口和身份文字，不重新渲染手帐编辑区。未改变文字输入、贴纸或作品保存逻辑。

## 管理员账号

原 4176 实例的登录名由 `admin` 改为 `宋静雯`，同步 `.local/admin-account.txt` 的用户名。服务重启使原管理员会话失效，需要重新登录。

迁移前的账号数据及回执备份在 `.local/admin-identity-backup-1788963980425/`，只保存在本机。对比确认密码散列、盐及 API 配置均不变；邀请码文件未修改。

用户在上轮之后已自行修改密码。初始回执中的密码与当前散列不符，本轮保留当前密码，不用初始密码覆盖。回执中的旧密码仍为历史初始记录。
