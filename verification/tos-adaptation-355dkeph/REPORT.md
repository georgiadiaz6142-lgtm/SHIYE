# TOS 适配第一阶段：账号与作品的本地验证

日期：2026-09-11。Song 授权开始低成本部署方案的第一步：本地存储适配验证。

## 实际完成

- `server/object-documents.ts`：一个对象内的数据分区共用快照、一起提交；条件不匹配时有限重试。未知写入结果不自动重放事务。损坏数据、超过文档容量不会覆盖已有内容。
- `server/tos-objects.ts`：对接官方 Node SDK 的窄接口适配层，上传使用目标 `if-match` / `if-none-match: *` 与内容校验。不把权限错误、桶不存在或网络失败当作空数据；不回显供应商错误详情。
- `server/work-storage.ts`：新增对象存储作品仓库和图片存储适配。保持账号隔离、图片不可变、现有作品版本和 operationId 幂等机制，图片先于可见元数据写入。
- `server/admin.ts`、`server/access.ts`：可注入同一个对象文档组，将管理员、普通账号、邀请码绑定和用户名唯一性检查放在同一原子单元。共享会话仅保存令牌摘要；重建服务对象后可恢复，退出、改密码对其他实例生效。受控加密密钥从部署层注入，错误密钥拒绝启动。
- `server/object-rate-limit.ts`：可共享的登录／邀请码尝试计数，过期清理、数量上限和哈希索引；登录失败审计在失败事务之外保存。
- 账户、管理、作品、文案及公共 API 路由改用异步身份解析。本机模式仍使用原有数据文件和会话行为。

`npm run build` 通过；完整后端测试 76/76 通过，0 跳过、0 失败。完整输出见 [backend-tests.txt](backend-tests.txt)。`git diff --check` 通过。

这些结果不等于真实 TOS 并发测试，也不等于真实进程或云容器重启验收。

4. 实际迁移本机账号和作品时，要明确迁移范围、保留原加密密钥及身份，不重建成另一个管理员。当前未读取或迁移个人数据。
5. 核对网关可信来源与真实客户端地址，再设置生产限流；当前路由仍使用 socket 地址，不能直接信任外部传入的代理头。
6. API 配置测试证明仍在实例内存中，需支持跨实例保存；账号组、审计、作品操作回执需要容量及归档策略。当前文档默认上限 24 MiB，超限拒绝保存而不删数据，不是无限扩展方案。
7. 减少共享身份文档重复读取、作品保存时重复下载校验全部图片的开销，实测请求、传输量及延迟后定预算。
