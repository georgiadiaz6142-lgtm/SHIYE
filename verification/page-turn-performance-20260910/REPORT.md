# 共用翻页性能与视觉优化 · 2026-09-10

【已完成】

- 首页演示、阅读、单双页编辑共用缓存画面翻页：正反两面各生成一张临时 PNG，动画切片引用同一图像，替代原先 40 条切片各复制两面的完整 DOM。桌面 18 条、触屏 12 条。
- 缓存仅存在于本机内存，最多 6 面，按页面内容、尺寸、像素比及工作区区分；退出或身份变化时清空。图片按已有同源资源读取，无新增上传。翻完仍使用原来的可编辑文字、贴纸及纸张数据。
- 两面解码完成前保留原正面，动画计时随后开始；取消后不往已移除层追加内容。捕获失败或超时回退为两面 DOM 翻转，不创建大量切片，不显示空白等待页。
- 全程约 800ms；保留跟手进度、取消回落和软纸弯曲，减弱过强透视。固定阴影模糊半径，逐帧只改变其位置、缩放和透明度；切片光照改为连续渐变。
- 去除切片重复边框，保持约 1px 覆盖处理抗锯齿细缝；统一编辑与阅读的书脊阴影、中心暗线及纸边明暗。

【同环境性能对比】

隔离 Chrome，1440×1000，每个动画面 24 个元素，使用相同的 1.45 秒采样窗口比较渲染性能（产品实际动画已缩短到 0.8 秒）：

| 指标 | 优化前（上一轮只读诊断） | 优化后 |
|---|---:|---:|
| 翻页新增 DOM 节点 | 4339 | 149 |
| 采样窗口内帧数 | 17 | 88 |
| 帧间隔 P95 | 133ms | 17ms |
| 超过 33.5ms 的帧 | 14 | 0 |

本次复杂页首次纹理准备约 179ms，简单页约 109ms，准备后开始动画；这是首次准备成本，不能将表中帧间隔当成点击到完成的总耗时。结果见 `performance.json`，脚本为 `probe.cjs`。

【实际验证】

- `browser.cjs`：8 组通过。对比原纸面与缓存 PNG（纹理纸、彩色粗体文字、旋转贴纸），平均颜色通道差约 4.12/255；验证阅读前后翻、单双页编辑、原位输入、取消准备、强制捕获失败回退、触屏 12 切片及首页照片演示。
- `gesture-regression.cjs`：11 组通过。保留按需工具面板、文字输入、元素移动、键盘删除撤销、鼠标/触控板/原生触摸翻页、双页配对、点击封面和同步刷新。
- `npm run check:prototype`：脚本语法及 10 项作品合并检查通过；`git diff --check` 通过。
- 已查看 25%、50%、80% 翻页截面及首页/手机截图；没有观察到中心白色布局间隙。静止左右页几何间距仍为 0px。用户设备上曾出现的白缝未在原测试中直接复现，不能声称所有设备已彻底消除。
- `live-assets.json`：4176 的 `app.js` 与 `styles.css` HTTP 200，内容匹配最新本机文件，刷新可用。

【范围及限制】本轮产品修改仅在 `app.js`、`styles.css`。保留其他未提交工作，无后端配置更改、真实 AI 调用、依赖安装或用户浏览器作品操作。测试为本机隔离 Chrome，未在物理手机、低性能设备或 Safari 上做性能/视觉验收；无法捕获的资源使用回退动画。首次图像生成有准备时间，运动中的画面分辨率受像素比与长边 1600px 上限约束，静止可编辑页面不受此上限影响。
