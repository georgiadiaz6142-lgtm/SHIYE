# 自动抠图失败诊断与弹窗 · 2026-09-10

## 已确认的原因

本机任务历史中记录了 3 次 `PROVIDER_TIMEOUT`、1 次 `PROVIDER_REQUEST_FAILED`。另有早期测试次数上限错误，属于已解除限制前的历史记录，本轮没有恢复限制。

三次超时均在创建任务后约 30 秒结束，标准化尺寸均为 2000×1125。最近一次失败时间为 2026-09-10 01:15:52（北京时间），耗时 30031 ms；保留的标准化 PNG 为 3,860,910 字节（约 3.68 MiB），base64 长度为 5,147,880，低于当前 10,000,000 的编码上限。因此该次失败没有被图片大小限制拦截。

历史日志未区分鉴权与图片处理阶段，也未记录底层连接失败细节。不能仅凭这些记录断言百度过载、网络断开或某张原图超过 10 MB；原图上传字节数未留存，其他已过期临时文件未恢复。

## 实际修改

- 上传前文件过大、格式无法读取，以及上传/任务提交/轮询返回的失败，使用独立原生 dialog 说明原因；关闭后保留当前工坊状态。普通选框操作错误也可看到具体提示。
- 失败任务按 jobId 去重；查询同一个失败任务不重复弹窗。重新打开页面后恢复失败任务时说明一次。弹窗不会覆盖正在使用的账号或导入对话框，错误仍留在工坊页面。
- 保留“不自动重新提交百度请求”的行为。查询原任务只读取本机任务状态，不表示可以向百度找回超时的同步请求结果。
- 保留后台 errorType 到前端，区分文件大小、编码后超限、2400 万像素上限、最短边不足、权限、额度、请求频率、HTTP 状态与超时。
- 百度鉴权单独使用最多 10 秒等待，图片处理使用 30 秒等待；鉴权未通过明确说明尚未向抠图接口发送照片。原实现两阶段共用 30 秒等待且错误类型相同。
- 百度 JSON 错误只提取已校验的数字错误码并映射说明；不回显上游错误原文、密钥、令牌或请求 URL。
- 未改变图片裁切、修边、命名和账号逻辑；未取消文件/编码/像素安全限制，未变更 API 密钥、账号、邀请码或现有无限次授权。

## 输入限制依据

本项目原文件上传上限为 10×1024×1024 字节；会先转为最长边 2000 像素以内的 PNG，再校验编码长度。PNG 转换和 base64 编码可能使小于 10 MB 的原文件仍然超限。

百度智能抠图接口要求编码后图片不超过 10M，最短边至少 128px、最长边不超过 3000px。以专用接口说明为依据，未套用其他图像 API 的 4M 限制：[智能抠图接口](https://ai.baidu.com/ai-doc/IMAGEPROCESS/rm8zl3koj)。数字错误码分类参考[百度图像处理错误码](https://cloud.baidu.com/doc/IMAGEPROCESS/s/Ek3bclpgv)，未识别的代码保留通用说明和数字码。
